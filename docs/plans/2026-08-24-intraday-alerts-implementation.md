# 盘中智能监控与提醒实施计划

关联设计：`docs/plans/2026-08-24-intraday-alerts-design.md`

## 阶段 1：领域模型与持久化

1. 在 `src/domain/types.ts` 增加提醒规则、规则类型、提醒等级、提醒事件、运行时快照和提醒中心状态类型。
2. 在 `src/state/alert-store.ts` 增加基于 `ExtensionContext.globalState` 的提醒配置存储，支持规则新增、更新、暂停、删除和未读状态管理。
3. 扩展 `src/data/portable-watchlist.ts`、`src/services/github-sync-service.ts` 的可同步配置版本，纳入提醒规则；未读、冷却和当日事件不写入同步数据。
4. 为旧版导入数据增加兼容迁移，缺失提醒字段时使用空规则集合。

验收：旧配置正常加载；导出、导入和 GitHub 同步能保留规则、阈值和开关，且不会覆盖本机运行状态。

## 阶段 2：提醒计算引擎

1. 新增 `src/services/alert-engine.ts`，消费每次 `MarketSnapshot`，输出标准化提醒事件。
2. 实现价格突破/跌破、涨跌幅、持仓盈亏和接近目标价等精确规则。
3. 实现最近 15 分钟的轻量时间序列缓存，支持 3 分钟快速涨跌和最新 1 分钟成交额相对均值判断。
4. 实现量比、换手率、大盘相对强弱和逆势表现规则；指数数据缺失时只跳过联动规则。
5. 加入交易时段、午休、闭市、停牌、数据过期和字段缺失判断。
6. 实现越线状态机：首次越线触发，持续满足不重复，恢复后可再次越线；同规则 10 分钟冷却。

验收：使用模拟行情可确定性触发每种规则；重复快照不会重复生成事件；断网或过期快照不会产生误报。

## 阶段 3：通知编排与命令

1. 新增 `src/controllers/alert-controller.ts`，连接 `QuoteService`、`AlertStore`、`AlertEngine` 和 VS Code 通知 API。
2. 普通事件只更新状态栏和提醒中心，重要事件使用 `showInformationMessage`/`showWarningMessage`，默认不播放声音。
3. 注册“新增盘中提醒、查看提醒中心、全部静默、发送测试提醒、标记已读、今日不再提醒”等命令。
4. 为通知按钮实现查看走势、跳转股票和当日静默操作。
5. 扩展 `package.json` 的 activationEvents、commands、菜单和必要配置项。

验收：普通提醒不弹窗；重要提醒仅首次越线弹窗；测试命令可在无行情时验证通知链路。

## 阶段 4：提醒中心与股票行交互

1. 扩展 `src/views/watchlist-webview.ts` 消息协议，支持打开设置、查看事件、暂停/恢复、删除和标记已读。
2. 在现有树状列表增加自动收起的提醒中心，按未读、今日已触发、已暂停展示。
3. 股票行显示低饱和未读小圆点和简短规则摘要，不改变现有一行布局、分组和持仓置顶结构。
4. 在股票右键/更多菜单增加“设置盘中提醒”；提供价格规则、预设规则和持仓快捷规则的紧凑表单。
5. 保持滚动、拖拽、分组折叠和输入框焦点行为不回归。

验收：无需离开自选股即可配置提醒；提醒中心默认不抢占列表空间；所有操作在浅色/深色主题可读且低调。

## 阶段 5：测试与质量门禁

1. 新增 `test/alert-engine.test.ts`、`test/alert-store.test.ts`、`test/alert-controller.test.ts` 和迁移/同步测试。
2. 覆盖边界值、二次越线、冷却、交易日切换、主备源切换、数据缺失、导入导出和 GitHub 冲突合并。
3. 使用假时钟和固定行情夹具，不依赖公网或真实交易时段。
4. 执行 `npm run check`、`npm test`、`npm run build`，再生成 VSIX 并在干净配置中安装验证。

## 阶段 6：版本与交付

1. 版本升级到 `0.1.34`（如期间有其他变更则按实际版本递增），更新 README 和变更说明。
2. 更新官网功能介绍、最新 VSIX 下载链接和版本号。
3. 提交插件仓库与官网仓库，推送 GitHub；记录安装、升级和“发送测试提醒”的验收步骤。

## 实施顺序

先完成模型、存储和纯计算引擎，再接入通知，最后修改 Webview。每个阶段独立提交；提醒功能异常时不阻塞行情刷新和现有自选股功能。
