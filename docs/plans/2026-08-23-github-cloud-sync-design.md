# GitHub 私有仓库云同步设计

## 目标

在保留本地 JSON 导入导出的基础上，增加 GitHub 登录、手动上传和手动同步，使持仓、自选股、分组、排序、关注状态与当前股票可以在多台电脑间迁移。

## 登录与远端存储

插件使用 VS Code 内置 GitHub Authentication Provider 请求登录，不自行保存访问令牌。首次使用时获取当前 GitHub 账号，并创建私有仓库 `a-stock-watch-sync`。仓库只管理 `watchlist.a-stock-watch.json`，数据格式复用现有版本化便携备份。

每次操作都验证仓库仍为私有。若同名仓库不存在则创建；若已经存在且为私有，则验证或初始化备份文件；若仓库为公开或远端备份格式不兼容，则拒绝读写。

插件全局状态只保存账号、仓库、最后已知文件 SHA 和最后同步时间，不保存 GitHub 令牌。

## 用户入口

自选股标题栏增加云同步入口，并在命令面板注册对应命令。云菜单提供：

- 上传到 GitHub
- 从 GitHub 同步
- 查看同步状态
- 解除绑定

本地导入导出继续保留，作为离线迁移和恢复手段。

## 上传与冲突保护

上传生成最新便携备份，再通过 GitHub Contents API 创建或更新远端文件。第一次绑定发现已有云端文件时，优先提示从云端同步；用户选择本机覆盖必须二次确认。

后续上传使用保存的 SHA 与远端当前 SHA 比较。远端已被其他电脑更新时不静默覆盖，提示先同步；只有用户明确选择并二次确认后才强制覆盖。成功后更新本地保存的 SHA 和同步时间。

## 下载与恢复

“从 GitHub 同步”读取并严格验证远端备份，默认使用现有智能合并策略：保留本机独有股票，重复股票采用云端配置。应用前生成本地恢复文件，写入失败时同时回滚自选股和当前股票。成功后记录远端 SHA 与同步时间。

## 错误处理与验证

登录取消、权限不足、限流、离线、仓库被删除或改为公开、远端文件超限、JSON 损坏和 GitHub 冲突都只报告错误，不改变本地数据。解除绑定只清除插件中的仓库关联，不删除远端仓库，也不注销 VS Code 的 GitHub 账号。

测试覆盖 GitHub API 请求与错误映射、首次建仓、已有远端数据、上传、同步、智能合并、SHA 冲突、公开仓库拒绝、损坏数据拒绝、同步失败回滚，以及命令和标题栏声明。
