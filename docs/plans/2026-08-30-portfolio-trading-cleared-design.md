# 持仓买卖流水与清仓记录设计

**日期：** 2026-08-30  
**状态：** 已确认，待实现

## 目标

在现有成本价/股数持仓基础上支持买入、部分卖出和自动清仓归档，持续记录每个持仓周期的已实现盈亏；同时修复顶部持仓区域滚动时遮挡普通自选股、无法正常滚动的问题。

## 交易与成本规则

- 每笔买入/卖出保存股票、方向、价格、股数、时间、备注和持仓周期 ID。
- 多次买入采用加权平均成本：`(原成本×原股数 + 买入价×买入股数) ÷ 新股数`。
- 卖出按卖出时平均成本计算已实现盈亏；部分卖出不改变剩余平均成本。
- 卖出股数不能超过当前持仓；价格必须大于 0，股数必须为正整数。
- 全部卖出时当前持仓归零，生成一条已清仓记录，保存买入/卖出金额、累计已实现盈亏、收益率、买卖次数、清仓时间和完整流水。
- 同一股票重新买入生成新的持仓周期；历史清仓记录不被覆盖。
- 清仓收益率为累计已实现盈亏除以该周期累计买入成本。

## 数据结构

新增独立 `PortfolioStore`，与 `WatchlistStore` 解耦：

1. 当前持仓汇总：股数、平均成本、买入金额、卖出金额、已实现盈亏、更新时间。
2. 交易流水：不可变交易记录和持仓周期 ID。
3. 已清仓记录：清仓汇总和该周期交易流水快照。

旧版本只有成本价和股数时，首次发生交易会自动补一笔“历史买入”流水，价格使用旧成本价，不改变原持仓结果。手工设置持仓仍可用作兼容入口，但买入/卖出是推荐操作。

## 界面和滚动

列表布局固定为：搜索工具栏 → 大盘走势 → 提醒中心 → 持仓 → 独立滚动的普通自选股 → 已清仓。

- 持仓区域固定在普通列表上方，超出高度时只在持仓内部滚动。
- 普通股票和已清仓共用独立滚动容器，完整支持滚到顶部和底部。
- 已清仓是普通滚动容器中的最后一个树节点，不参与拖拽、不遮挡其他内容，默认折叠。
- 股票菜单增加“买入”“卖出”“查看交易记录”；卖出全部股数后自动刷新到清仓区域。
- 清仓和持仓使用中性色与紧凑行距，保持现有低调 VS Code Explorer 风格。

## 同步、导出与异常

- 导出和 GitHub 同步包含当前持仓、交易流水、已清仓记录和折叠状态。
- 交易流水按交易 ID 合并，相同 ID 以更新时间较新的记录为准。
- 删除自选股不删除持仓历史；删除清仓记录必须二次确认。
- 导入旧格式不包含投资组合字段时保持现有行为；导入新格式时对持仓和流水执行校验。
- 导入事务同时回滚自选股、当前股票和投资组合，避免出现半更新状态。

## 验收标准

- 多次买入、部分卖出、全部卖出的成本与已实现盈亏计算正确。
- 全部卖出后进入底部已清仓；重新买入产生新持仓周期。
- 旧版成本价/股数首次交易时无损迁移。
- 持仓内部可滚动，普通列表不遮挡持仓且可完整上下滚动。
- 导出、导入和 GitHub 同步不丢失交易流水和清仓记录。
- 原有行情、提醒、三大指数、分组、关注和拖拽功能回归通过。
